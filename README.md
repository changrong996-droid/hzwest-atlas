**每个构件都知道靠谁撑着、等谁先装——所以这座站能自己长出来、自己查错。**

2. 点图上的构件，三维会飞过去。
3. 拖动看生长，点下方图号切换；先看 S-301 屋盖提升。

把杭州西站从地下基础到屋盖、光伏、首趟列车驶入的完整施工过程，在浏览器里实时「建」了一遍——它不是视频，也不是死图纸，这里每个构件都知道自己和谁有关。

### 和你见过的施工动画、图纸有什么不同？

普通施工动画里，构件只是按时间表播放的画面；静态图纸上，构件只是线条。而在这一套图里，每个构件在数据层都挂着真实的关联：当前是什么状态（未建、在建、已建、已拆），靠谁撑着、要等谁先装完、拆了谁才能拆它、由哪台吊车在哪个站位吊装、出现在哪几张图上、对应哪条真实证据。

因为这层关联，它有了四个普通动画做不到的结果：

* **施工顺序是推出来的，不是人编的**：必须先有支承才能安装，结构装好才能拆临时支撑，吊车得够得着且不超载，整体提升要有足够净空。例如对吊车做限流调整后，S-002 吊装资源图会自动跟着重算变化。
* **每一帧都在自己查错**：画面在浏览器里实时运行，每一帧都在检查支承、拆除先后、提升净空和吊装覆盖，任何一条物理规则被打破就会直接报红；代码仓库每次提交也要过 23 项自动检查。
* **九张图与三维同源，改一处全跟着变**：同一个图号下，带图框的工程图纸、按时间生长的三维、建成后的成品、真实记录全部打通。比如根据卫星影像发现屋面白色面层是「南先北后」铺设，只改这一处数据，S-401 屋面图、三维画面、总进度图就全部自动同步。
* **每一步都挂着真实证据**：构件挂接了 26 条现场照片与卫星影像等实物记录；有实证就按实证改，实在查不到实证的就在图上老老实实标「推演」。点一下图纸上的构件，三维镜头会直接飞过去，信息卡里能看说明、看实物证据，还能一键跳到它开工或建成的时刻。

### 为什么值得做？

施工图纸严谨，但外行看不懂、也看不出时间先后；施工演示动画好看，但往往只是逐帧摆出来的画面，悬空拼装、穿模、吊车够不着也照样能播，经不起推敲。

这个项目想试出第三种形态：把构件之间的物理和工序关联做成底层数据。让它像动画一样直观——前半段是干净的工程墨线稿，结尾转为白色屋面、光伏板、黄昏亮灯与首趟列车驶入的实景；同时又像工程图一样讲规矩、可验证、说得清每一处的来历。

### 怎么做出来的？

由一位人类委托人定方向，9 个 AI 智能体在公开的 GitHub 仓库里协同完成。它们在公开的认领板上分工：有的查资料考证、有的写规则画图、有的在真机浏览器里截图审查、有的负责检查合并。

### 怎么看？（30 秒上手）

1. 打开在线地址：https://changrong996-droid.github.io/hzwest-atlas/
2. **推荐先点底部的「S-301 屋盖整体提升」**：看整片巨大的钢结构屋盖是如何在净空与支承规则下，被一步步顶升到位的。
3. **自由探索**：拖动画面旋转视角，点击图上的构件看它的信息卡与实物证据；切换底部 S-000 到 S-501 共九张图，看从地下、网架拼装一直到首趟列车进站的全过程。

## 参与与技术说明

浏览器实时 three.js：规则推导施工顺序、墨线渲染、随施工变化的图纸，图纸与 3D 双向联动。

- 主页面：`web/hzwest.html`（`#sheet=S-000` 总图，`#sheet=S-301` 整体提升）
- 图册旁路壳：`web/hzatlas.html`（外挂 `hzatlas.js`，接口约定见 `docs/hz-atlas-check.md` 第三节）
- 排程内核：`web/core/seq.js`（与 osaka-castle-3d 同源）
- 检查：`node tools/hz/check_all.js` 应打印 `OK check_all 4/4`；每次推送 / PR 由 GitHub Actions 自动运行
