# 任务书 · 构件上下游关系（relations）

**委托人批准（2026-11-10）**：「点一个构件，它的上下游关系在图纸和三维里同时亮起」——这是和动画、静态图纸拉开差距的地方。必须**分层**（委托人：信息太多，要分层）。

宿主部分（hark-cr，分支 `agent/hark-cr/relations`）已做：关系接口 `HZ.rel`、图纸与 3D 同时高亮、`ctx.rel` 交给模块、检查 `check_rel`。卡片第 2 / 3 层归 hark-cs（D-44，见第五节）。

## 一、三层

| 层 | 什么时候 | 显示什么 | 谁做 |
|---|---|---|---|
| 1 | 点一个构件 | 只亮直接关系：**上游**（撑着它 / 要先装）**蓝** `#1f63c6`，**下游**（它撑着 / 等它）**绿** `#13955a`，选中本身**黄** `#f2b705`；其余变淡。图纸（插件图）与 3D 同时。点空白或 Esc 清除。 | 宿主（已上线） |

## 二、接口 `HZ.rel(sheet, partId, t, opt?)`（`web/hzrel.js?v=1`，在 `hzseq.js` 之后、`hzview.js` 之前加载）

纯函数、无 DOM。只读引擎已有数据，**不手写关系表**：

- **构件级支承**：`hzseq.js` 的 supRule 用同一个 R1 判定（盒顶面贴合 / 侧挂 / host）时，顺手把「谁撑着这一件」记到引擎构件的 `p.supP`（Set）。排程不读它，只给关系用。
- **工序级先后**：`core/seq.js` 推出的 `a.pred`（`why` 现有：R1 61 条、R3 81、R4 41、served 38、erect 10、R5 2、R8 2）。
- **吊车**：`HZ.assignCranes` 写的 `p.crane`（`HZ.cranes` 下标：0–5 外围塔吊 `crane`、6–7 云门塔吊 `ycrane`、8–11 内侧塔吊 `tcrane`）/ `p.crawl`（履带吊站位 `[x, z]`）；屋盖网架行（`p.grp` 1–4）记为本区液压提升器。

返回 `null`（本图此刻没有这件）或：

```js
{
  sheet, id, label, t,
  n,                // 这件代表的引擎构件数
  nested,           // false | 'inside'（被更小的盒分光，退回盒内全部）| 'overlap'（薄盒，退回与盒相交的永久构件）
  up:   [项],       // 上游
  down: [项],       // 下游
  counts: { hold, wait, carry, next, rmWait, rmNext },
  crane:  { kind: 'tower'|'crawler'|'lifters', idx, id /* S-002 的 T<n>，没有为 null */, name, station: [x, z]|null, zone?, n, sheet } | null,
  cranes: [同上…],  // 成员分到的全部吊车，按件数降序；crane = 第一台
  sheets: [{ sheet, name, id|null }],   // 这件出现在哪些图（按各图声明的范围工序；S-001 给出 K-<工序> id）
  acts:   ['deckS', …],                // 这件所属工序（含 ~rm）
  records: ['R-0009', …]                // HZR.forPart(sheet, id) 的记录 id
}
// 项：
{ sheet, id, label,
  rel: 'sup' | 'seq' | 'rm',   // sup = 支承（靠谁撑着 / 它撑着谁）；seq = 工序先后（等谁先装 / 谁等它）；rm = 拆除顺序（拆之前要等 / 它拆之前要等它）
  level: 'part' | 'act',       // part = 构件级（supP）；act = 工序级（pred）
  why, whyText,                // 'R1' 支承、'R3' 工序先后、'R4' 临时设施、'R5' 同一套设备、'R8' 提升扫掠让路、'erect' / 'served' …
  act,                         // 引擎工序 key
  here: [本图 id],              // 本图上代表这一项的可点构件（图纸 / 3D 高亮用）
  n,                           // 构件级：涉及几件；工序级：该工序构件数
  state }                      // t 时：0 未开工 · 1 在建 · 2 已完成
```

- 本图上的构件级项：`sheet` = 本图、`id` = 本图 part id。其余项（构件级但对方不在本图、工序级）一律 `sheet: 'S-001'`、`id: 'K-<工序>'`（去掉 `~rm`），即总进度横道图上的那一行，可直接 `#sheet=S-001&focus=K-…` 跳过去。
- `counts.hold` = 上游 sup 项：构件级按件数、工序级按 1 计；`wait` = 上游 seq 项数；`carry` / `next` 同理为下游。`rmWait` / `rmNext` 是拆除顺序（如塔吊「拆之前要等」它服务的工序），**不进第 2 层三行**。
- 「开通」里程碑被规定在全部工序之后，对每件都成立、信息量为零，两头都不计。
- 不可枚举属性 `.hl = { self, up, down }`（引擎构件 Set）给宿主 3D 着色用，JSON 里看不到。
- 辅助：`HZ.relParts301()`（S-301 的 J01–J24 提升器 + ZS / ZM / ZN 合成构件）、`HZ.relAll(sheet, t, parts)`（检查用）、`HZ.relWhy`（why → 中文）。

**图纸构件 → 引擎构件**：S-001 按 `K-<工序>`（整道工序 + 其拆除）；S-301 按提升器 / 分区；其余按 `part.box` 紧包（容差 0.6 m），每件引擎构件归包它的**最小**盒（一张图内是一个划分，所以构件级关系上下对称）；某盒一件也没分到时退回「盒内全部」，再没有退回「与盒相交的永久构件」（S-101 的剖面薄盒）。

## 四、宿主实现（`hzview.js?v=33`、`hzseq.js?v=15`、`hzrel.js?v=1`）

- 选中插件构件（图纸点、3D 点、`#focus=`）→ `HZ.rel(SHEET, id, t, { parts: 本图缓存 parts })` → `__pv.rel`；`modsPick` 的 ctx 多一个 `rel`。取消（⌂、Esc、点 3D 空白、**点图纸空白**（新）、切图）→ 清。
- 3D：主网格 / 墨线新增顶点属性 `aRl`（0 其余 · 1 选中 · 2 上游 · 3 下游）+ 统一开关 `uRel`。墨线填充与实景都按 `hzRel()` 着色（其余压向纸色 72%），墨线线条其余降到 13% 淡墨；**图纸范围外的上下游也照画**（如股道下的线下框架柱），未建的上下游画设计位半透明轮廓。
- 图纸：插件 `draw` 之后，宿主在同一视图变换下把选中 / 上游 / 下游 `hit` 框以外压淡（纸色 66%），三类框描色，左下一行图例「■ 上游 撑着它 N · 要先装 N ■ 下游 它撑着 N · 等它 N · 点空白 / Esc 清除」。插件不用改。
- S-301（宿主自画图）：选中提升器 / 分区时 3D 同样亮起（`__pv.rel`），**图纸叠层没做**（千斤顶图是 hzsheet.js 自画，hit 结构不同），也**不走 pick 钩子**（§3 第 12 条：S-301 的选择不走此钩子，保持不变）——所以 S-301 上暂时没有卡片。
- 状态：`__pv.rel`、`__pv.relN`（三类引擎构件数）、`__pv.relRects`（图纸上描了几个框）、`__pv.relSets`、`__pv.relOf(id, sheet?)`。

## 七、已知风险

- **大盒稀释**：S-501「站房屋盖」一类的大盒一件就代表 927 件引擎构件，上游会列出几百件（`counts.hold` 很大）。卡片第 2 层宜写「N 件」而不是逐项列。
- **工序级项亮整道工序**：例如选中一个提升孔，「要先装：柱头连接」会亮全部 24 个柱头。这是引擎只有工序级数据的真实结果；若嫌多，可在卡片上标「（整道工序）」。
- **S-101 剖面**：4 个节点（标注类）没有任何引擎构件，`rel` 返回空清单；7 个按 overlap 认件。
- **3D 着色只在选中时开**（`uRel`），每次选中要整段重写 `aRl`（约 34 万顶点量级的 `fill`），实测为一次性操作；拖时间不重算（关系与时刻无关，只有 `state` 随时间变）。
