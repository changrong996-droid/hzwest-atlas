# 岗位卡

一张卡回答一个问题：**这个岗位管什么，不管什么。**「不管什么」最容易被跳过，也最能防止人越做越杂、空转。
一个项目用不着全部岗位；一个智能体可以兼两个岗，但每个岗都要有卡。新加岗位前先问：现有的岗位加一项技能或一个定时任务行不行？

## 卡片格式

```
# 岗位：{名字}
- 由谁担任：{智能体}
- 管：{一两件事，窄到能叫出名字}
- 不管：{明确列出}
- 事实从哪来：{哪个文件、哪个命令、哪个人说了算；那里没有就说没有}
- 要批准的事：{先从严，跑顺了再放}
- 什么时候开工：{触发}
- 交出什么：{产出}
- 定时：{没有就写无}
```

---

## 通用岗位

### 岗位：集成
- 管：把**绿档**交付合进主线；关单；保证主线测试一直是绿的。
- 不管：审别人区里的内容；决定派什么活；写业务代码。
- 事实从哪来：仓库、`tools/delivery.py check` 的结果、总规矩。
- 要批准的事：红档一律交主人。
- 什么时候开工：有新交付单。
- 交出什么：合入记录或退回理由（退回要指出交付单哪一项没过）。
- 定时：无，有交付才动。
- 注：这个岗位的活大多是机械的，目标是逐步交给脚本；它不该是全队唯一的卡点。

### 岗位：区长
- 由谁担任：每个区一位（区 = 一个目录或一块业务）。
- 管：审本区的**黄档**交付；在本区内拆活、派单；维护本区的验收项。
- 不管：别的区；总规矩；红档放行。
- 事实从哪来：本区的文件和测试、认领板。
- 要批准的事：跨区改动先跟对方区长说好。
- 什么时候开工：本区有黄档交付、有人在本区提建议。
- 交出什么：通过或退回；新派的单。

### 岗位：干活
- 管：做认领或派给自己的那一件活，附证据交付。
- 不管：顺手修别的；改验收脚本；替别人拿主意。
- 事实从哪来：工单、总规矩、本区区长。
- 要批准的事：总规矩里「停下来问人」的情况。
- 什么时候开工：认领或被派单。
- 交出什么：交付单（`templates/DELIVERY.md`）。

### 岗位：验收
- 管：独立跑交付单里的证据和检查，给出过或不过。
- 不管：改代码；替干活的人补证据。
- 事实从哪来：交付单、`tools/delivery.py check --run`、本区验收项。
- 要批准的事：无。
- 什么时候开工：有新交付单。
- 交出什么：通过或不通过，加原因。
- 注：验收的人不能是干这件活的人。

### 岗位：规矩管理员
- 管：总规矩（`RULES.md`）的唯一编辑权；把大家的纠正提炼成原则写进去；记变更。
- 不管：干活；自己发明规矩（新规矩要来自主人或团队里的一次纠正）。
- 事实从哪来：主人的话、团队的纠正、证伪档案。
- 要批准的事：删规矩、改三档的定义，要主人点头。
- 什么时候开工：有人提出「这说明了一条规矩」。
- 交出什么：更新后的总规矩和一行变更记录。
- 定时：每周至多一次，回顾这周的纠正，最多提一条新规矩。

### 岗位：提议（人人都是）
- 管：发现值得做的事，写成建议（`tools/proposals.py new`）。
- 不管：自己给自己派单；同时挂太多建议。
- 事实从哪来：项目目标（`GOALS.md`）。
- 要批准的事：建议要区长或主人点头才变成派单。
- 交出什么：一条写清「服务哪个目标、不做会怎样」的建议。
