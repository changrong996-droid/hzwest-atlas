# 提案：防腐化三件套——模块清单即合同、预算棘轮、熵超标自动冻结

提出：hark-liuzhijie（2026-11-23 开单 #48，P1）· 起草：fo-changrong · 2026-11-24 · 状态：提案，等委托人裁定采纳与否；不影响任何在途单。

## 要解决的事（三笔账，都是实数）

**模块账**：`web/mods/` 现有 18 个模块共 5,890 行（`ctx/` 子目录另有 7 个文件），`hzwest.html` 241 行里挂载行 16 条、带 `?v=` 版本号。挂载点与模块依赖只有集成人手上有账，成员互相看不到。#51（联合冒烟发现 harness 的 THREE 桩缺 Vector4）就是模块间口径漂移到合入后才暴露的一例。

**只增不减**：第二批每稿都是纯新增（platform、tour、trains-ops、yungu…），没有任何检查项或流程授权删旧；`hzwest.html` 与模块总量只会单调上涨。

**预算账**：8,192 字节是**单稿**软上限，仓库**总量**没人盯——没有检查项看 hzwest.html 行数或模块总行数的变化率。

这三条和委托人 11 月定的方向（从更高层主动治理规则、给规则层瘦身）是同一件事的工程版：治理不该靠事后整理，要有机检兜底。

## 机制一：模块清单即合同

新文件 `docs/modules.md`，每模块一行表格：模块名｜一句话职责｜导出符号｜挂载点（hzwest.html 行号）｜owner｜状态（active / deprecated）。挂载行号由集成人填（接线归集成人的规矩不变）。

三条可机检规则 → 新检查项 `tools/hz/check_manifest.js`（严格档）：

1. `hzwest.html` 挂载的每个 `mods/*.js` 必须在清单里；
2. 状态为 deprecated 的模块不许再被挂载；
3. 新增模块先补清单再动挂载（清单与挂载同稿走）。

收益：接线、评审、做减法共用同一本账；孤儿挂载和重复符号类问题在账面先抓，不用等联合冒烟。

## 机制二：预算棘轮

清单里给每模块记一行当前行数作预算。`tools/hz/check_budget.js --strict`：实际行数 ≤ 预算即过；想涨预算必须在**同一稿**里删掉等量旧行（棘轮只紧不松），或由集成人裁定放开。防的是「小改」悄悄变「重写」。

## 机制三：熵超标自动冻结

三个可测指标（先粗后细，不玄学）：

1. `hzwest.html` 每个合入点的净增行数；
2. 清单外的孤儿挂载数；
3. `check_all` 考卷项数增长 vs 通过率。

任一越阈（首次建议：hzwest.html 单日净增 > 200 行，或孤儿挂载 > 0），集成人用门已有能力 `plan freeze` 暂停建新单，直到一张「减法稿」（删/并模块、清孤儿）合入再 `unfreeze`。门侧 zero 新增设施。

## 落地顺序（全部可逆、纯新增）

1. **manifest 稿**：先交 `docs/modules.md` 草案（现有 18 模块 + 职责 + owner，挂载行号留集成人补）+ `check_manifest.js` 规则 1/2；
3. **棘轮**：`check_budget.js` 先 report 档跑一周只记数，数据稳了再转严格（同 check_fpv 先例：#50 报告档起步、#52 待口径落地转严格）；
4. **熵指标**：先只随 check_budget 输出，阈值观察两周再定，freeze 只在阈值有数据支撑后启用。
