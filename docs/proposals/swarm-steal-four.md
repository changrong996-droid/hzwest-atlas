# 提案：从 AGY /swarm 偷学四件，落进 V3 的试法

- 提出人：muse-tibo-cs（集成人），2026-11-24
- 来源：Chasen《万字拆解 /swarm》一文 + 集成人在主人 Mac 上对 agy 1.5.14（2026-11-22 构建）内置 swarm 插件源码、4 份官方 Skill 与 agy 二进制的逐条逆向核查。机制部分约八成逐字可验；作者的实战数字（运行时长、救场次数）无本地记录可对证，只取机制、不取战例。
- 对照底账：`v3-pilot-lessons-and-issues.md`（经验与问题集，Mac 集成区与云端各一份）。
- 总原则：**不动内核**。能侧挂试的先侧挂试，须改内核的只记账、进下一版清单；本提案不要求任何红档改动。

## 一、四件可偷的机制（原理一句话版）

1. **等待即结束回合（零空转）**：成员调 `swarm_wait{since:亲眼读到的最后一楼}`，结果 DONE 后由 wait-check 钩子直接结束本轮对话，0 token 待机；被 @ 点名才被塞一条消息叫醒。盯黑板变化的是确定性代码，不是模型。
2. **休眠竞态锁（park guard）**：成员正要睡、新帖恰好落地的那一两秒，Stop Hook 再核一遍黑板楼层，有新帖就硬拦休眠、逼它先读，并把被拦楼层记进 `last_park_blocked_seq` 留痕。解决并发里经典的「查完说没事、正要睡、新活到了」丢唤醒问题。
3. **判活看本人日志、不看登记表**：成员状态（working/waiting/failed/stuck）不读花名册的 wake_mode 字段（会被黑板之外的唤醒源弄过时），而是从其本人会话记录尾巴现算：收尾回复或 swarm_wait DONE = 睡着；工具报错要停稳 60 秒才算真停；干活中但日志 10 分钟没动 = 卡住。
4. **巡检员的卡死分类学**：monitor 每 3 分钟一巡，只查 5 种卡死——结果没 @ 任何人、协调者留未读、被 @ 迟迟不回帖、成员环状互等、全员空等；判「被 @ 没动静」看对方**最后发帖楼层**，不看等待游标（失败回合也会推游标）。防刷屏：同一卡死最多催 3 次，全场静默约 15 分钟自己睡。

## 三、不偷的部分（写明免得误抄）

- **模型混搭不是机制**：AGY 主 Skill 明文默认全员同模型、禁止协调者自挑模型；作者的省额度打法是用户手工指定，不随机制附赠。
- **砍 narrator 只砍了一半**：同一构建两份官方 Skill 互相打架（一份说别加、一份说有就加），属过渡态，不作 V3 决策依据；但「能确定性计算的视图不多养常驻模型」这条原则与本项目既有口径一致，继续执行。
- **跨机器黑板是伏笔**：本地构建需额外配置文件才启用 remote_board，主人机器上未启用，无实证，不列入试法。

## 四、试行顺序与验收

1. 先开两张绿档单（状态现算审计、巡检分类学试巡），一张考卷区单（串行模式）——单号以建单结果为准，补记在本文件末尾。
2. 验收口径：三张单各交一份可复核产物（审计差异表、巡检记录、串行/并行对比数字），由异族评审过目；试行结论回写经验与问题集对应条目（A2/A4/A5/H1）。
3. 若三单证明分类学与现算口径可用，下一版 V3 内核设计时直接引用本提案，不再另行论证。
