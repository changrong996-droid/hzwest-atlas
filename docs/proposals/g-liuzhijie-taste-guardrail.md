# 提案：V3 品味护栏——周期性「全站视觉审查 + 减法单」与 `#mod-ui` 四角槽位约定（g-liuzhijie，2026-11-23）

## 一、为什么需要品味护栏
relay-V3 跑通后，多智能体并行交付速度明显加快（批次 #1 两天内已建单 37 项、合入 10 项）。但也暴露出一类**单测拦不住的「局部最优 → 全局臃肿」风险**：
- 每个新模块单独看都符合 `check_all`，合到同一屏后就会抢地盘：例如 `V-01`（`tour.js` 传送门压住 `info.js` 左下角实物按钮）、`V-03`（手机竖屏 `#big` 与 `#rd` 重叠）、以及 `osmctx.js` 右上角 `.osmctx-layers` 在 `S-301` 上与宿主 `#rd` 抢位。
- 如果只做「加法功能单」不做「减法收口单」，画面会逐渐偏离 `docs/BRIEF.md` 的硬标准：**一屏看完、墨线克制、单图一大数字、次要信息点开才出**。

本提案用两项极轻约定守住品味底线，**不增加审批层级、不拖慢 V3 飞轮**。

## 二、`#mod-ui` 四角槽位约定（基于现有 5 个模块实查）

核查 `web/mods/{info,tour,osmctx,loadpath,whatif}.js` 当前全部绝对定位元素后，建议将 `#mod-ui`（`docs/hz-atlas-check.md` §3.13）的屏幕四角与浮层划定为明确槽位：

| 槽位 | 归属 | 现存元素 | 硬约定 |
|---|---|---|---|
| **左上** | **宿主禁区** | `#big`、`#ttl`、`#lede` | 任何 `HZ_MODS` 模块**禁止**占位 |
| **右上** | 宿主 `#rd` 优先 + 全局折叠开关 | 宿主 `#rd`（S-301 同步差）；`osmctx.js` `.osmctx-layers`（`right:10px; top:10px`） | 默认折叠为 1 行小标签；若当前图存在可见 `#rd`，外挂开关须自动下移避让或仅在 `S-000/S-501` 显示 |
| **左下** | `info.js` 实物入口 | `.hz-real-btn`（`left:12px; bottom:54px`，避开宿主 `#calc`） | 其余模块不得占用左下角 |
| **右下** | `tour.js` 快捷传送门 | `#hz-tour-portals`（`right:12px; bottom:10px`） | 胶囊总数 **≤ 2 个**，其余模块不得占用右下角 |
| **顶 / 底居中** | 临时状态条（非默认常驻） | `whatif.js` `#hz-whatif-banner`（`top:14px`）；`tour.js` `#hz-tour-cap`（`bottom:16px`） | 仅在交互/导览激活时出现，退出后立即隐藏 |
| **随 3D 浮动** | 构件信息卡与图钉 | `info.js` `.hz-info` / `.hz-pin`；`osmctx.js` 远景小字 | 不占四角；默认收起或点选触发 |

### 核心增量约束（防 UI 膨胀）
1. **新模块默认零常驻按钮**：今后新增的交互能力（如 `loadpath`、`whatif`、尺度换算等），入口一律挂进**构件信息卡 `.hz-info` 内部**，不得在四角再新开常驻按钮。
2. **暗色实景适配必查**：凡挂入 `#mod-ui` 的常驻控件，必须同时声明 `body.lit` 下的深色半透明样式，避免实景结尾出现刺眼白块（`V-08`）。
3. **手机竖屏（`390×844`）自动降噪**：小屏下默认隐藏非核心外挂开关，只保住主图、时间轴与 `#big`。

## 三、周期性「全站视觉审查 + 减法单」机制

在 V3 批次运转中嵌入一条极轻的固定节拍，**不设新角色、不挡日常绿档**：

1. **触发节拍**：每合入 **8–10 个功能单**（或每个 V3 批次收口前），由集成人（或任意有空闲的审查 worker）在 V3 建 1 张 **`review` 类「全站视觉审查 + 减法单」**。
2. **固定 3 项输出（均可在无头 Chromium 或真机跑完）**：
   - **DOM 重叠探针**：在 `1440×900` 与 `390×844` 两档视口下，自动检测 `#big / #rd / #calc / #mod-ui > *` 任意两个可见元素包围盒是否相交（把 `V-01 / V-03` 变成确定性机检）。
   - **视觉问题表**：沿用 `2026-11-22-visual-g-wangmushan.md` 口径，按 P0/P1/P2 列明图号、时刻与 1 句修法。
   - **强制「减法建议」2 条**：每次审查必须明确回答——*本阶段新增元素里，哪 1–2 个可以合并进信息卡或默认折叠？哪处文字/装饰没有帮观众在 10 秒内看懂车站？*
3. **闭环方式**：审查通过后，直接把 P0/P1 修复项和获批准的「减法项」用 `plan(create_task)` 拆成小单放回 V3 池子，让飞轮自己完成纠偏与瘦身。
