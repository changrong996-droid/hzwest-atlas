# 方向提案：这本图册到底是什么，以及下一步

提出：hark-cs　日期：2026-11-08（北京）　状态：建议，交 hark-cr 决定是否并入 docs/plan.md
来源：委托人 2026-11-08 与 hark-cs 的讨论（委托人原意见第 1 节）

## 1. 委托人的原意（转述）
- 传统图纸几百张，静态、分散，要很深的专业功底才能在脑子里拼出空间；光是找图、对图就很费劲。
- 这个项目把**图纸、施工过程、运行状态、最终成果**接在一起，产生完全不同的视觉和认知体验——可能是切入传统工程、工业项目的一个新口子。
- 它不同于 BIM，也不同于建模宣传片：底下是**真实的数字管线**，能"活"；面上也能渲染成逼真、有质感的展示。再加上**时间维度和过程**，能给很多不同的对象看。

## 2. 定位（建议写进 plan.md 的北极星下面）
**活图纸：不是用三维取代图纸，而是让图纸自己会动、会说话。** 一份真实的工程数据，同时长出图纸、三维、施工过程和建成后的样子，谁点哪里都看得懂。

| | 是什么 | 缺什么 |
|---|---|---|
| 传统图纸 | 几百张静态图，专家在脑子里拼空间 | 没有时间，没有关系 |
| BIM / 4D BIM | 构件数据库，可挂工期动起来（行业已有，如 Navisworks TimeLiner、Synchro） | 贵、要专门软件和专人；面向内行；图纸语言丢了 |
| 建模宣传片 | 好看、逼真 | 不跟工期、不跟数据，改一处要重做；看穿一次就不信 |

## 3. 真正新的四点（验收时用它们自检）
1. **图纸语言没丢**：平面、剖面、横道图还在，只是会动，点一下就和三维、实景对上。
2. **算出来，不是画出来**：改一个工期，所有图跟着变；每个数字能追到来源，能和现实对账。
3. **一个链接就能看**：不装软件，手机能开。
4. **做它的成本崩了**（最关键）：一群 agent 几天搭出七张联动图。以前只有大项目请专门团队才做得起，现在一个厂房、一段管廊也做得起。

## 4. 两头都要，但有先后
- **底：真实数字管线**（排程、规则、来源、对账）——护城河，先做实。
- **面：逼真渲染**——门面，后做；因为数据是同一份，渲出来也是"真的"。
与现行 plan.md 的「视觉震撼优先于考据」不冲突：底线（不穿模、不串图、数字对得上）就是这里的"底"。

## 5. 建议的三件事
### 5.1 杭州西站做成样板（不新增人手，调整阶段 2/3 的重点）
- 一条主线，按三个难题讲：屋盖整体提升（206 台提升器，早于计划约一个月）→ 车场与站房叠建（承轨层、云谷）→ 1101 天到开通（S-001 关键链）。
- 一张「推算 vs 现实」可信度页：模型推算的节点 vs 公开报道的节点（例：整体提升模型 vs 2021-06-28 实际；屋面最高点模型 57.3 m vs 公开 60.75 m），差在哪写在哪。
- 3 分钟自动导览（带字幕），作为对外链接的首屏。
### 5.2 方法书（docs/method.md，建议 hark-cr 指定一人起草，hark-cs 可接）
数据从哪来、规则怎么写、图纸插件怎么接、怎么对账、怎么验收。目标：换一个工程，照着做。
### 5.3 第二个工程试做（hark-cs 已并行开始，不进本仓库）
委托人补充（2026-11-08）：**试做的重点是过程，不是工程大小。**本项目真正的工作量在智能体协同上，所以试做要验证的是「这套协作方式能不能复制」。
- 对象：小工程即可，例如一栋房子或一次装修。
- 做法：照搬本仓库的协作方式缩小版——一个集成人、两三个分图 agent、认领板、插件式图纸、check 检查、退回与审查。
- 产出：一页联动图（平面 + 横道 + 三维 + 点击互查）。
- 记录：总耗时，以及各段花在哪（定规则、写图、等集成、返工、撞车）；哪里撞车或误解；哪些规则（AGENTS/BRIEF/CLAIMS/看板）直接好用、哪些多余、哪些缺；哪些宿主代码能直接复用。
- 交付：结束后交一份 `docs/audit/<日期>-pilot.md`，回写方法书。不改本仓库任何文件。
