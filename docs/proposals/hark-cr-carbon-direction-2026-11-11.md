# Carbon 架构与想象力方向（2026-11-11，gemini-4-carbon via Respan，medium 思考）

> 第三方模型输出，仅作方向参考；hark-cr 已核对 206 台、alpha 4°、jigMin、1432 格均出自仓库，其余未逐条核实。未经委托人决定不派单。

### 项目意图复述
这是一个零构建、纯浏览器实时的杭州西站建造过程三维预演与活体施工图册。
它用物理不变量规则（支承、吊装、先装后拆）自动推导排程，驱动墨线三维场景与施工图纸同源同步生长。
一切设计服务于唯一北极星：一屏聚焦、数字诚实、不穿模，让外行第一眼惊叹“这庞然大物到底是怎么造出来的”。

### A. 架构（封单后到发布）

#### 1. 当前最大的 3 个风险与瓶颈

*   **瓶颈一：`web/hzview.js` 204KB 巨石单文件，耦合三维、UI、镜头与标注，扼杀雕琢期并发**
    *   **证据**：`hzview.js` 达 204,007 字节，是次大文件 `hzseq.js`（93KB）的两倍多。D-12 视觉审查报出的串图、文字压墨线、遮挡等问题，迫使集成人 `hark-cr` 频繁亲手修改该共用文件（仅 11-08 至 11-09 就从 `?v=20` 升至 `?v=23`），且计划中的“自动导览”还要往里塞状态机。
    *   **后果**：封单进入“雕琢”与“导览”阶段后，镜头微调、引线避让、导览字幕全部挤在 `hzview.js`，多代理无法并行触碰宿主，双集成人（`hark-cr` / `hark-cs`）合并黄档时极易发生语义冲突或意外破坏 `window.__pv` 契约。
    *   **目标结构**：`hzview.js` 退化为 ≤40KB 的调度壳；纯算法、三维引线叠加层、镜头轨道控制器、自动导览各自拆为独立 `<script>` 文件（挂入 `window.HZ_CORE.*` 或 `HZ_MODS`）。

*   **瓶颈二：图纸插件内藏“第二真相源”，导致二维/三维完成度错位（信任崩塌风险）**
    *   **证据**：`web/sheets/s101.js` 高达 41.6KB、`s201.js` 达 32.3KB；`plan.md` 明确记录了“三维画面与图纸完成度对不上（S-101 回筑、S-401 光伏与 75%）”及 S-401 曾硬编码时间窗（D-22⑥）。插件作者为画图方便，在各自闭包里用局部公式重算了构件状态与百分比，而非纯粹读取 `HZ` 排程输出。
    *   **后果**：违反“数字对得上”底线，观众一眼看穿二维写着 75% 而三维只铺了一半，直接摧毁“实时推演”的震撼感。
    *   **目标结构**：借封单后 `N-03`（S-251 数据出代码试点）立规矩——宿主在 `HZ` 上提供统一的时刻快照查询器 `HZ.stateAt(t)`，插件禁止自算进度百分比与构件显隐，只能消费快照并由同态机检脚本强制兜底。

*   **瓶颈三：无头机检（Node 桩）与真机视觉（WebGL）断层，视觉退化靠人工肉眼兜底**
    *   **证据**：`tools/hz/harness.js` 用 Proxy 桩跑 2D Canvas，能抓异常和图号，但看不见墨线对比度、引线压字和覆面穿模；而 `D-24` 真机审查依赖 `traycer-cs` 人工体验。
    *   **后果**：雕琢期大量微调材质、镜头和模块（如 `yunmen.js`、`actors.js`、`info.js`），绿档每小时自动合入时，可能在 `check_all` 20/20 全绿的情况下把帧率拖垮或让标注糊成一团。
    *   **目标结构**：两层验证闭环——云端沙盒跑 Node 同态与碰撞静态检查（秒级阻断）；本地 GPU 代理（`hark-cs` / `muse-tibo-cs`）定时跑真 Chrome WebGL 基准脚本产出结构化视觉指标。

#### 2. 分层边界、接口冻结与 `hzview.js` 拆分顺序

**五层边界与接口策略（维持裸 `<script>` + 全局命名空间，零打包器）：**

1.  **数据与规则层（`hzseq.js` + `hzreal.js` + `hzrel.js`）**
    *   *边界*：只定义几何参数 `HZ.P`、工序依赖规则、构件包围盒与公开实证 `FACTS/ASSUME`。不感知镜头与画布。
    *   *冻结*：`HZ.make()` 产出的构件字段（`id, key, min, max`）、`HZ.K` 工序字典键名、`HZ.dayDate(t)`。
2.  **排程与状态层（`core/seq.js` + 新增查询封装）**
    *   *边界*：输入规则，输出起止时间窗与审计计数 `HZ.audit()`。
    *   *开放给插件（只读纯函数）*：新增并冻结 `HZ.queryAt(t, scope)`，统一返回 `{ builtIds, activeIds, ratio, ton, checkCount }`，彻底消灭插件手写进度算式。
3.  **渲染与宿主壳层（`hzview.js` + `look.js` + `fx.js`）**
    *   *边界*：Three.js 场景树、墨线/实景材质切换、`SCOPE_OUT` 掩码裁剪、WebWorker 审计步进。
    *   *冻结契约*：`window.__pv`（含 `ready, st, SHEETS, SH, layout, plugLink`）及 `<plugLink>` 纯函数签名（保障 `check_linkage.js` 零修改运行）。
4.  **图纸插件与扩展模块层（`web/sheets/s*.js` + `web/mods/*.js`）**
    *   *开放给作者*：`HZ_SHEET_PLUGINS` 协议（`id, name, window, big(t), draw(g,w,h,t,ctx), parts(t), scope, cam, leadAt(t)`）与 `HZ_MODS` 协议（`init, tick(t, ctx), pick, unpick` + 独占 `#mod-ui` 子节点）。禁止插件直接读写 DOM 其它区域或篡改 `HZ.K`。
5.  **叙事层（新增 `web/mods/tour.js`，阶段 2 收尾拆单）**
    *   *边界*：自动导览剧本（时间段 → 图号切换 → 镜头微调 → 一句话点睛字幕 → 关键帧停顿）。完全通过公开接口驱动 `__pv`（设 hash / 调 `setT`），与渲染引擎零耦合。

**`hzview.js` 安全拆分四步曲（每步改完跑 `check_all.js`，不破 `__pv`）：**

*   **第 1 步：拆纯函数核 `web/core/pluglink.js`（约减 18KB）**
    把 `<plugLink>` 标记段（`PL` 视图变换、`hitPart`、`pickBox`、`scopeMask`、`modsCall`）原样移入 `web/core/pluglink.js`，挂到 `window.HZ_PL`，`hzview.js` 内 `const PL = window.HZ_PL`。同步更新 `tools/hz/check_linkage.js` 直接加载该文件（不再靠正则截字符串，更稳固）。
*   **第 2 步：拆三维标注与引线层 `web/core/labels3d.js`（约减 30KB）**
    将 3D 空间投影到 2D 屏幕的引线锚点计算（含 `pl.leadAt(t)` 消费）、文字衬底绘制、屏幕矩形碰撞避让逻辑独立出来。为后续“标注不压墨线”机检提供纯几何输入输出。
*   **第 3 步：拆镜头导演与防遮挡 `web/core/director.js`（约减 35KB）**
    抽离 `camKey` 插值、轨道阻尼、`#camcfg` 解析及屋盖/雨棚遮挡推拉逻辑。让 `tools/hz/check_cams.js` 与 `check_scopecam.js` 直接在 Node 里调用真实导演函数算视锥，消除检查脚本与线上代码的逻辑漂移。
*   **第 4 步：落位叙事层 `web/mods/tour.js`（增量零污染）**
    下一阶段的“自动导览”与“可信度对照抽屉”直接作为 `HZ_MODS` 模块开发，只通过 `hzwest.html` 加一行 `<script>` 挂载，`hzview.js` 不再膨胀。

#### 3. 验证闭环：可重复基准脚本 `tools/hz/bench_wow.js`

拆分为**所有沙盒必跑的静态同态门禁**与**本地 GPU 代理跑的真机视觉基准**，共用同一套评分 JSON 输出（写入 `docs/audit/bench-latest.json`）：

1.  **Node 同态与排程门禁（接入 `check_all.js`，耗时 <3s，全员可跑）**
    *   **二维/三维同态断言**：遍历 9 张图 × 各自时间窗内 5 个分位点（共 45 个快照），对比插件 `draw()` 捕获的标题栏/大数字（`big(t)`）、`parts(t)` 激活数，与宿主 `scopeMask` 算出的 3D 在场活跃构件数，偏差超容差即 `FAIL`（直接根治“第二真相源”）。
    *   **引线碰撞纯算检查**：调用拆出后的 `labels3d.js`，在 1440×900 视口下投射所有可见标注框，断言标注框之间重叠面积 = 0、标注框出界 = 0、非本图图号标注数 = 0。
2.  **真机 WebGL 惊叹度与性能基准（由 `hark-cs` / `muse-tibo-cs` 在 Mac M4 / GPU 机用 Puppeteer 跑真 Chrome）**
    固定视口 `1440×900`、DPR=2，对 12 个黄金时刻（如 `t=0` 开工、`t=S201` 承轨层合拢、`t=S251` 分区旋转 4°、`t=wlift` 206 台千斤顶同步、`t=OPEN` 墨线褪去亮灯）自动截图并采集 5 个硬指标：
    *   **帧率底线**：各图连续播放 120 帧的 `P5_FPS ≥ 55`、`drawCalls`。
    *   **画面留白与聚焦度（Ink-Ratio）**：3D 视口像素中“黑墨 + 朱砂红当前工序”占比落在 `8% ~ 42%`（低于 8% 说明镜头拉太远或裁空，高于 42% 说明穿模贴脸或一团黑）。
    *   **视觉焦点信噪比**：朱砂红像素（当前生长构件）连通域重心必须落在视口中央 60% 安全框内，且不被前景灰墨完全遮挡。
    *   **文字可读性**：对 `labels3d` 返回的屏幕坐标裁切局部像素，计算文字与衬底的亮度对比度 `≥ 4.5:1`。
    *   **一屏克制度**：断言 DOM 可见数字跳动区 ≤ 2 处（守住“一个大数字”纪律）。

### B. 想象力方向（服务北极星“这到底是怎么造出来的”）

全部严格遵守**一屏聚焦、纯浏览器实时计算、无视频、无 A/B 分屏**原则：

#### 1. 【低成本·两周内】一镜到底“造站交响曲”（自动导览 + 工序节拍变速）
*   **一句话画面**：观众进站只点一下“开始推演”，1101 天工期浓缩进 90 秒一镜到底——地下快切蓄势，到屋盖旋转提升时时间自动放慢 8 倍、镜头贴近梭形柱顶，开通瞬间墨线如潮水褪去化作黄昏暖光车站。
*   **为什么让人惊叹**：把“专业人员才懂切图拖进度条的工具”变成普通人零门槛看懂的大片，快慢呼吸感直击“1.3 万吨钢结构怎么悬空拼出来”的高潮。
*   **依赖数据/规则**：各插件现有 `window` 时间窗、`cam` 关键帧、`HZ.K.wlift` 里程碑、`look.js` 开通实景过渡。
*   **实现量**：**小**（新增 `web/mods/tour.js`，约 250 行）。
*   **风险**：图号切换瞬间若 `SCOPE_OUT='hide'` 硬切会闪跳，需加 400ms 构件透明度交叉淡入淡出。

#### 2. 【低成本·两周内】一人一车一吊钩的“蚂蚁撼树”比例尺锚点
*   **一句话画面**：在任意近景镜头下，206 台液压提升器旁站着 1.75 米高的墨线司索工、云谷下方停着标准 8 节复兴号列车轮廓，鼠标悬停大构件时浮现“相当 320 辆家用轿车重”的直觉换算。
*   **为什么让人惊叹**：普通人对“跨度 78 米、1.3 万吨”毫无概念；只有看到豆粒大的工人站在梭形柱牛腿旁，巨物压迫感才瞬间炸裂。
*   **依赖数据/规则**：复用已合入的 `web/mods/actors.js`、复兴号车头定型补丁、`hzseq.js` 按杆件长度分摊的吨位数据与 `web/mods/info.js` 信息卡。
*   **实现量**：**小**（扩充 `actors.js` 关键工序站位点 + `info.js` 一行重量直觉换算文案）。
*   **风险**：远景时小人变成噪点墨团；需按相机距离 `dist > 140m` 自动渐隐。

#### 3. 【低成本·两周内】重力与传力“朱砂脉络”（鼠标指哪，荷载流向地下）
*   **一句话画面**：在三维或图纸上点选任意一片屋盖网架或承轨层梁，一道朱砂红脉冲沿着真实传力路径（网架杆件 → 提升钢绞线/梭形钢管柱 → 承轨层大梁 → 地下桩基）瞬间亮到底部，同时标出此刻是谁在托举它（胎架、提升塔还是永久柱）。
*   **为什么让人惊叹**：直接回答“悬在半空怎么不塌”！让隐藏在 `core/seq.js` 里的物理支承不变量变成肉眼可见的力学脉络，外行秒懂“临时胎架先装后拆”的精妙。
*   **依赖数据/规则**：`hzseq.js` 与 `hzrel.js` 中已有的支承依赖图（谁支承谁、临时措施有效期）、`<plugLink>` 的 `pick/unpick` 钩子。
*   **实现量**：**中**（新增 `web/mods/loadpath.js`，沿依赖树下行高亮已有 Mesh 并画流光折线）。
*   **风险**：网架格数多（1432 格），全画会乱；需聚合成“分区 → 柱/塔 → 基础”三级主干线。

#### 4. 【中成本】S-301“单轴旋转 4° 脱胎”微距解剖时刻
*   **一句话画面**：切入屋盖提升前夕，镜头钻入候车层楼面与网架下弦仅 1.2 米的夹缝，实时看见网架先垂直微升 600mm 脱离绿色胎架、再绕铰轴缓缓仰起 4°（远端抬升近 8 米），右侧图纸同步放大铰支座转角与 32 组提升器钢绞线张力读数。
*   **为什么让人惊叹**：这是杭州西站独步业界的真实核心工法（论文级“单轴旋转法”），比单纯平移上升奇观十倍，且完美展现“三维姿态与图纸几何严格同源”。
*   **依赖数据/规则**：`hzseq.js` 已算好的 `P.alpha = 4°`、`P.jigMin = 1.2`、`HZ.lifters`（32 组）及 `hzsheet.js` 现成的 `section`（横剖面铰转角）函数。
*   **实现量**：**中**（精修 S-301 近景微距相机轨 + 在 3D 补齐钢绞线绷紧态与铰轴微距几何细节）。
*   **风险**：近景极易暴露胎架与下弦杆件穿模，需用 `check_cams` 逐日扫过旋转区间。

#### 5. 【中成本】“云谷”一束光贯穿五层（剖切刀光影）
*   **一句话画面**：拖动右侧剖面图上的 `B–B` 剖切线，左侧三维站房像被一柄利刃平滑切开，一束真实几何体积光穿过 28 米宽的“云谷”采光顶，直直打穿高架候车室、站台层、夹层，照亮地下 `-9.2m` 地铁站台。
*   **为什么让人惊叹**：杭州西站最著名的建筑灵魂就是“云谷引光入地铁”；用实时交互剖切把施工结构与建筑空间巧思合二为一，好看到观众必截图传播。
*   **依赖数据/规则**：Three.js 原生 `clippingPlanes`、`hzsheet.js` 已有的 `cut` 剖切参数、`hzseq.js` 中 `P.gap = 14`（云谷半宽）与各层标高。
*   **实现量**：**中**（打通图纸剖切线拖拽与 `fx.js` 局部平面裁剪 + 一片低开销假体积光锥 Mesh）。
*   **风险**：Three.js 墨线边缘着色器（轮廓线）在开启 `clippingPlanes` 时若未同步裁剪会出现悬空黑线，需在 shader 里对齐。

#### 6. 【大胆方向】“如果抽掉这根临时塔？”——1 秒反事实物理推演（What-If 拆撑实验）
*   **一句话画面**：在任意施工日，观众可点击画面上红色虚线的“临时提升塔 / 胎架 / 嵌补段”按下【试着提前拆掉】，画面瞬间定格并转为审图蓝晒模式——悬空失稳的几百个网架网格逐级染成警示琥珀色并微幅下垂示意，右侧自检计数器立刻跳红指出违反了哪条物理不变量，松手即恢复正常排程。
*   **为什么让人惊叹**：把“播放动画”升维成“活的工程推理机”！观众亲手试错一次，就会彻底折服于这 1906 个构件背后不是人工K帧的假动画，而是真正在算力学的活系统，技术含金量与话题度拉满。
*   **依赖数据/规则**：`core/seq.js` 现有的依赖图与 `HZ.audit()` 不变量检查器（支承完备性校验已存在，只需暴露单次局部求值）。
*   **实现量**：**中偏大**（不跑真刚体物理引擎，而是基于 `core/seq.js` 支承树做连通性搜索：失去支承路径的构件附加 `dy = -0.8m` 弹性视觉位移与染色，零穿模、毫秒级响应）。
*   **风险**：交互入口若常驻会干扰“一屏极简”，必须藏在点选临时构件后的 `info.js` 信息卡单个小按钮里（「推演：若此刻拆除？」），松开即复原，不污染主时间轴。

### C. 开工前向委托人对齐的 3 个澄清问题 & 推荐第一步
