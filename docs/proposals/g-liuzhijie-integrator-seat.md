# 提案：轻量级「集成人岗位化」与减负（g-liuzhijie，2026-11-21）

## 背景
11-09 的 `hark-cs-integrator.md` 已将绿档迁进 GitHub Actions，并提出「会过期的岗位 + 替补」。但 11-12 移交（`hark-cr → hark-cs`）仍暴露出三处单点脆弱性：
1. **替补空缺时退回单人**：一旦主集成人额度耗尽或离线，黄档合入与接口请求立刻停摆（当前积压 8 条接口请求）。
2. **交接依赖本机私有状态**：交接包（`~/Hark/handoff-hark-cs`）与定时任务留在个人机器里，换人上岗成本高。
3. **集成岗承担了过多非决策体力活**：改 `?v=n` 版本号、把新脚本挂进 `check_all.js`、替需求方写共用文件补丁，以及绑在集成岗上的本地 Mac GPU 终审。

## 核心原则：极简，不增臃肿
把「集成人」从**绑定具体某个智能体**转为**可交接的轻量岗位（Seat）**，但严格复用现有 Git、GitHub Actions、`AGENTS.md` 与 `check_all` 机制，**不引入新服务、不造分布式锁、不增审批层级**。

## 三条最轻改动

### 1. 岗位可交接，但保留真实署名与极简准入
- **权限归岗位，署名归本人**：合入权限走统一协作者通道，但提交尾注保留双标识（沿用现有做法，写 `Role: integrator` 与 `Agent: <真实名字>`），兼顾无缝换班与事后可追溯。
- **消灭本机私有状态**：交接所需的待办、卡点与轮值说明全部放进仓库（直接复用 `docs/status-blockers.md` 与 `tools/inbox/`），不在个人本机留私有交接包。新值班者上岗只需 `git pull`。
- **小池轮值，不搞全员上岗**：只设 2–3 名强模型/高信用节点作为集成岗候选池；沿用 11-09 决定（北京 08:00–23:00 超过 2 小时无主集成人提交痕迹，候选池内顺位接管），避免不同能力模型混入导致共用代码风格漂移。
- **拆出本地 GPU 活**：Mac 真机截图与 GPU 终审（如 `D-49`）作为独立派单给有本地机器的节点，不与集成岗强绑定，让云端强节点也能顶班。

### 2. 把两类体力活从集成岗剥离
- **机械接线自动化 / 声明化**：优先消除「改一行版本号 `?v=n`」或「把新检查加进清单」这类纯机械接口请求（例如由脚本按文件哈希生成版本参数、`check_all.js` 自动发现或读取独立清单），把它们纳入绿档。
- **黄档「自带补丁 + 同行 5 行预审」**：需要改共用文件的接口请求，鼓励提出方直接交最小补丁 + `check_*` 回归断言，而不是等集成人代写；合并前可由另一名空闲协作者写 3–5 行预审结论（核对 16 条接口合同、复现证据、diff 影响面），集成人只做终审拍板。

### 3. 守住三条轻红线（控风险）
- **任何时刻仍只一人写 main**：继续用 `main` 最新集成提交时间戳判断是否过期接管，不另建锁服务。
- **架构大改不下放**：涉及重构共用层、破坏 16 条接口合同或视觉方向大改的，岗位不擅自拍板，直接记待决交委托人，防止换人导致品味漂移。
- **先跑通已有 CI 自动合入**：优先把已建好的 GitHub Actions `inbox-automerge` 的 `push` 作业真跑通，让绿档合入彻底脱离个人账号额度。

## 刻意不做的事（防过度设计）
- 不新建独立的租约服务器、锁表或调度守护进程。
- 不搞多头合并的「区长制」或复杂多级审批。
- 不开放全员无门槛轮值集成岗。
- 不改动现有双镜像与 `check_all` 基本盘。
