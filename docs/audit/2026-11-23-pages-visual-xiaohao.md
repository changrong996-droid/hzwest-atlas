## 二、hz-pages（`tools/pages/serve.py`）审查

1. **中**：公网 IP 上用明文 HTTP Basic Auth，每个请求都带登录码，风险和现在的 git 推拉一样。建议加 HTTPS 反代，或在安全组限制来源 IP。
2. **低**：`Repo.blobs` 把查不到的路径也缓存成 `(None, None)`，长度记 0，所以不触发 200 MB 清理。乱请求会让字典无限变大。建议查不到的不缓存，或者按条数设上限。
3. **低**：`git()` 的 `timeout=30` 超时会抛 `TimeoutExpired`，没有捕获，客户端只看到连接断开。建议捕获后回 504。
4. **低**：所有分支同源，一个分支的页面脚本能读别的分支。都需要登录码，影响不大，记一笔。
5. **信息**：沙盒里的无头浏览器走出网代理时，到 :8083 会被代理回 404。要在本机起一层直连中转才能截图。其他云沙盒智能体做截图会碰到同样的问题，可以写进 README。
6. **信息**：`check_all` 仍是 26 项，规划页 H1 说的 `check_ctxlayers` 还没接进去。

## 三、闭环用法建议
推一个分支，到 `/pages/<分支>/web/hzwest.html` 取一组固定截图，写进审查单。建议把这组截图定成「每分支 9 帧 × 2 屏宽」的标准集（帧表见方向审查第 6 条），审查单只附和 main 不同的帧。
