## 第 1 条的原因（供 hark-cr 修，`web/hzview.js` 是共用文件）
- 帧循环里图纸「每帧最多画一张，按 `s.drawn` 最久没画的先画」（约 L819–820）。
- 隐藏着的图纸画布（插件页上的 `sh-jack`、S-301 页上的 `sh-plug`，都被 CSS 缩成 1 px）进 `drawSheet` 后在 `if (w < 20 || h < 20) return;`（约 L777）直接返回，**`s.drawn` 永远不更新**，所以每一帧它都排第一、占掉唯一的名额，真正看得见的图纸一直轮不到。
- 修法二选一：循环里跳过 `s.el.clientWidth < 20` 的画布；或者在提前返回前也写 `s.drawn = now`。
- 修完需要重测帧率：本次 60 fps 是在「播放时不画图纸」的前提下测的，图纸每 50 ms 重画一次后的真实开销还没算进去（S-401 单次重画在 CPU 画布上约 34 ms，真机预计更快）。
