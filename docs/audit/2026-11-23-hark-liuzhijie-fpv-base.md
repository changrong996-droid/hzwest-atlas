## 航线格式
```js
HZ_FPV.add({
  name: 'route-xxx',                       // 小写字母数字连字符，URL #fpv=route-xxx
  title: '一句话说明', author: 'agent 名',
  day: [1096, 1118],                       // 选填：飞行中 3D 工期日从 day[0] 线性走到 day[1]
  landmarks: [{ name: '云门洞', pos: [0, 34, 208], r: 20 }],   // 选填：声明经过的地标
  keyframes: [{ t: 0, pos: [x, y, z], look: [x, y, z] }, ...]  // ≥ 4 帧；t 秒，0 起严格递增，末帧 ≤ 14
});
```
- 坐标系同宿主（x 东西、y 高、z 南北，南为 +，站房中心为原点）。
- 变速只由关键帧 `t` 间距表达。位置与目标点各自按非均匀 Catmull-Rom（三次 Hermite，切线 = 前后两帧差 ÷ 时间差）插值，速度连续。
- 片时 s 对应航线时 `t = s − 50.2`，末帧之后停在末帧，FPV 段到 64.2 秒结束。

## 开发自检判据（fpv-selfcheck.js）
每条航线 0.02 秒取样，3D 工期日随 `day` 走：
1. **穿模**：宿主自己的碰撞盒 `__pv.solidAt(x,y,z,1.0)`（楼板、柱、墙、云门、站台、雨棚，和镜头防撞同一套数据），命中即 FAIL，报秒数、坐标、构件包围盒。
2. **穿屋面**：屋盖网架不在碰撞盒里，另按 `HZ.rho ≤ 1` 且 `HZ.Hs − 1 < y < HZ.Hc + 1` 判。
3. **入地**：`solidAt` 返回 ground 即 FAIL。
4. **变速**：0.1 秒速度序列的显著极值（峰、谷交替，落差 ≥ 最高速 15 %）≥ 3 个。
5. **平顺**：视线角速度 ≤ 150°/秒；速度 > 3 m/s 时航向角速度 ≤ 180°/秒。
6. **地标**：`landmarks` 每项最近距离 ≤ r。
7. **近景参照**：穿越机的尺度感和速度感靠身边掠过的东西（柱、楼板沿、连廊、站台）。0.1 秒取样，在宿主镜头视锥（竖直 28°、16:9）内打 8×5 条视线，命中实体 / 屋盖 / 地面距离的第 25 百分位记为近景距离；近景距离 ≤ 30 m 的时间须 ≥ 60 %。
8. **空镜**：视线没命中或命中在 300 m 外算「空」；任一取样空视线 > 60 % 即 FAIL（末 2 秒收尾回望豁免）。
另报（不判）：最小净距档、最高速、最大加速度、每 0.5 秒的近景距离与空视线比例（viewTrace，调航线用）。

## 自检实测（无头 Chromium + SwiftShader，2026-11-23）

- **route-classic（按新判据重做）OK**：南广场 4.5 m 低空 → 擦云门西侧壁穿洞 → 27 m 贴楼面钻南檐口、从 5F 连廊下方钻过 → 候车层 2.4 m 高离树状柱 8 m 掠过 → 从云谷楼板缺口下潜，贴北侧站台沿 6 m 冲刺 → 东端回身拉升回望屋面。净距 ≥ 1 m、近景占 63 %、最差空视线 48 %、最高 89 m/s、视线 128°/秒、航向 142°/秒，速度极值 谷 3.9 s / 峰 5.4 s / 谷 6.8 s / 峰 8.1 s，四个地标都经过。
